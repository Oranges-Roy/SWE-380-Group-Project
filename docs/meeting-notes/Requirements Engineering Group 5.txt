	A skill is a folder containing a SKILL.md file with natural-language instructions for an LLM agent, optionally bundled with scripts and reference files. The agent loads a skill at run time when it judges the task matches the skill's description. Anthropic introduced the format in October 2025. The dataset harvested every file matching SKILL.md via GitHub code search, then classified each by location_class:
* canonical .claude/skills/<name>/SKILL.md: 9.8%

* elsewhere: 34.8%
86.6% of distinct contents have valid YAML frontmatter. The population is public GitHub only, a snapshot from July 2026: 3,797,117 file occurrences, 1,877,981 distinct contents, 282,200 repos, and 195,841 accounts.

	#7
	The release is v1.0.0: a SQLite DB (agent_skills_release.db, or agent_skills_sample.db for the 277 MB sample) plus a Parquet mirror on Hugging Face. It has four tables:
* artifacts: one row per SKILL.md occurrence, with primary key (repo_full_name, path). It has 3.8M rows (29,786 in the sample). Only rows with dedup_primary = 1 carry the content, frontmatter, and commit history.
* artifact_siblings: one row per bundled file or folder next to a representative skill. It has 7.26M rows (47,829 in the sample).
* repos: one row per repo, with primary key full_name. It has 282,200 rows (11,841 in the sample).
* mining_runs: one row per discovery run (7 rows), holding provenance metadata.
The joins:
* artifacts.repo_full_name = repos.full_name (1:N)
* artifact_siblings joins to artifacts on (repo_full_name, artifact_path = path)
* file_sha groups verbatim copies across repos

	#8
	Scope limits: The data covers public GitHub only and is a lower bound. Code search indexes default branches only, files under 384 KB, and repos with fewer than 500k files. Forks were included only if they had more stars than their parent, which left just 3 forks.
Legacy files: The results include lowercase and non-standard files, some with history going back to 2014, before the spec existed.
Deduplication: 50.5% of occurrences are verbatim copies. Only the primary representative is enriched, so copies may have different folders and histories that go unobserved.
Commit history: It is only sampled (458,548 files, flagged by history_fetched) and follows the current path only, so renames distort first_commit_at.
Folders and content: Sibling listings are capped (composition_truncated), content over 100 KB or non-text content is omitted, 0.9% of files were deleted before retrieval, and some skills are symlinks.
Authorship: Authors are keyed hashes. There is no label for human-written vs LLM-generated skill text, and emails and names are masked.
Unanswered by the sources:
* How many non-canonical or invalid-frontmatter files are real agent instructions
* Which script languages dominate the bundled siblings
* How often renames occur
* What share of skills are symlinks
